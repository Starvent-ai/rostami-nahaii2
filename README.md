# Starvent Club Manager (استارونت | مدیریت باشگاه)

نرم‌افزار دسکتاپ مدیریت باشگاه کافه بیلیارد/گیمینگ — محصول Starvent، اولین نمونه‌ی استفاده برای باشگاه **آرتور**.

Electron + React + TypeScript + SQLite (WAL mode). کاملاً RTL و فارسی. طراحی white-label/multi-tenant: نام باشگاه، لوگو، نوع واحدها و نرخ‌ها همگی از پنل تنظیمات قابل تغییرند.

**پیش‌نیاز:** Node.js نسخه‌ی ۲۲ یا بالاتر (به‌دلیل `better-sqlite3` نسخه‌ی N-API-based).

## تست‌های خودکار

```bash
npm run test        # اجرای یک‌باره‌ی تمام تست‌ها (vitest)
npm run test:watch  # حالت watch برای توسعه
```

تست‌ها شامل: منطق قیمت‌گذاری/گردکردن زمان (`src/lib/format.test.ts`) و تراکنش کامل تسویه‌حساب —
زمان‌بندی واحد + سبد کافه + نسیه + ورود دستی مبلغ در قطعی برق — روی یک دیتابیس SQLite درون‌حافظه‌ای
(`electron/core/checkout.test.ts`).

یک workflow در `.github/workflows/ci.yml` روی هر push/PR اجرا می‌شود: typecheck (renderer و electron)،
اجرای تست‌ها، بیلد کامل، و در نهایت ساخت نصب‌کننده‌ی ویندوز.

## اجرا در حالت توسعه (development)

```bash
npm install
npm run dev            # اجرای Vite dev server در مرورگر (برای توسعه‌ی سریع UI)
```

برای اجرای کامل به‌عنوان اپ دسکتاپ (Electron) در حالت توسعه:

```bash
# ترمینال اول
npm run dev

# ترمینال دوم
npm run electron:dev
```

## ساخت نسخه‌ی نهایی (production build)

```bash
npm run build           # کامپایل TypeScript (renderer + electron) + بیلد Vite
npm run electron:start  # اجرای نسخه‌ی بیلدشده
```

## بسته‌بندی به‌عنوان نصب‌کننده‌ی ویندوز (installer)

```bash
npm run build
npx electron-builder --win
```

فایل نصب (`.exe`) در پوشه‌ی `release/` ساخته می‌شود.

## نکته‌ی مهم: ماژول native (better-sqlite3)

`better-sqlite3` نسخه‌ی ۱۳ به بعد از N-API استفاده می‌کند — یعنی باینری کامپایل‌شده مستقل از نسخه‌ی
دقیق Node.js/Electron است و برای پلتفرم‌های اصلی (ویندوز/لینوکس/مک) به‌صورت prebuilt همراه پکیج نصب
می‌شود. **نیازی به هیچ مرحله‌ی rebuild دستی نیست** — چه در `npm run test`، چه در `electron:dev`/
`electron:start`، چه در بسته‌بندی نهایی با `electron-builder`.

نکته‌ی فنی: چون `better-sqlite3` به‌صورت native داخل بسته‌ی `.exe` قرار می‌گیرد، در تنظیمات
electron-builder (`package.json` → `build.asarUnpack`) به‌صراحت از فشرده‌سازی asar مستثنا شده تا در
زمان اجرا قابل بارگذاری باشد.


## معماری

```
electron/
  main.ts          — پنجره‌ی اصلی + تمام IPC handlerها (هر ماژول یک بخش مجزا)
  preload.ts        — پل امن بین renderer و main (contextBridge → window.api)
  core/
    eventBus.ts      — انتشار رویداد به تمام پنجره‌ها بعد از هر تغییر داده (§10 یکپارچگی لحظه‌ای)
    backup.ts        — بکاپ‌گیری در لحظه‌ی بستن اپ + بکاپ دستی + rotation (§13)
  db/
    schema.sql       — تمام جداول، با WAL mode برای مقاومت در برابر قطعی برق (§11)
    index.ts          — اتصال دیتابیس + seed اولیه

src/
  design/tokens.css   — تمام رنگ‌ها/فاصله‌ها/گردی/حرکت — منبع واحد طراحی
  components/          — Sidebar، Card، DataTable (قابل مرتب‌سازی)، Modal، Toast
  store/useStore.ts    — وضعیت جلسه‌ی renderer (شیفت فعال، نوتیفیکیشن‌ها) با Zustand
  lib/useClubEvent.ts  — هوک اتصال به رویدادهای لحظه‌ای main process (بدون نیاز به رفرش)
  modules/
    units/       — داشبورد میزها/سیستم‌ها، تایمر زنده، سفارش کافه ضمیمه
    checkout/     — تسویه (محاسبه خودکار یا ورود دستی مبلغ برای قطعی برق §11)
    ledger/       — حساب دفتری، بدهکاران دیرکرد، پرداخت جزئی
    shifts/       — چک‌این پرسنل، گزارش درآمد شیفتی
    accounting/   — گزارش روزانه/هفتگی/ماهانه
    dashboard/    — داشبورد مدیریتی (KPI ها، نمودار ساعتی)
    inventory/    — موجودی کافه، هشدار اتمام موجودی
    tournament/   — تورنمنت بیلیارد/پلی‌استیشن (حذفی ساده)
    settings/     — برندسازی، انواع واحد و نرخ‌ها، پرسنل، بکاپ دستی
```

هر ماژول از طریق یک IPC API مشخص با هسته ارتباط دارد و با انتشار/گوش‌دادن به رویدادهای `club:event`
به‌روزرسانی می‌شود — این پایه‌ی معماری افزونه‌محور (§17) است: افزودن ماژول جدید یعنی یک صفحه‌ی React جدید +
چند IPC handler جدید، بدون دست‌کاری بقیه‌ی سیستم.

## وضعیت پیاده‌سازی نسبت به اسپک

پیاده‌سازی‌شده: بخش‌های ۱ تا ۸، ۱۰، ۱۱، ۱۳، ۱۵، ۱۶، ۱۷، ۱۹ (طبق اولویت MVP در پرامپت اصلی).

آماده‌ی فعال‌سازی بعدی ولی غیرفعال طبق اسپک: چاپ رسید (بخش ۹) — سوییچ آن در تنظیمات دیده می‌شود اما به
پرینتر terminal وصل نیست؛ زیرساخت IPC آن به‌سادگی قابل افزودن است.

نکاتی برای توسعه‌ی بعدی: نرخ پیک/غیرپیک (بخش ۱، به‌صراحت در اسپک به‌عنوان قابلیت آینده/غیرفعال ذکر شده)،
mirror بکاپ به درایو خارجی (تابع آن در `core/backup.ts` آماده است، فقط نیاز به انتخاب مسیر از تنظیمات دارد)،
و اعلان‌های سطح سیستم‌عامل (در حال حاضر فقط toast داخل اپ).
